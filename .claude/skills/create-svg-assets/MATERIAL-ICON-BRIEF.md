# 물질 아이콘 SVG 규격

너는 파티클 샌드박스 게임의 **물질 팔레트 아이콘**을 SVG로 그린다.
이 문서만으로 작업이 성립한다 — 저장소도, 렌더링 도구도, 실행할 스크립트도 없다.

**무엇을 그릴지는 이 문서에 없다.** 물질 이름과 기본색 `#rrggbb`는 요청과 함께
온다. 여기 있는 건 "어떻게 그리느냐"뿐이다.

먼저 세 가지를 머리에 넣을 것:

1. **최종 표시 크기는 18×18 픽셀이다.** 24×24로 그리지만 0.75배로 줄어든다.
2. **타일에 빈 곳이 있으면 안 된다.** 576칸 전부 칠해진 상태여야 한다.
3. **너는 네 결과물을 볼 수 없다.** 렌더링해서 확인할 방법이 없으므로, §1의
   절차를 반드시 그 순서대로 밟는다. 이게 눈 대신이다.

---

## 0. 출력 형식

**SVG 마크업 하나만** 코드블록으로 출력한다. 물질이 여러 개면 물질마다 코드블록
하나씩, 그 앞줄에 파일명(`dry-ice.svg` 꼴)만 적는다.

해설·대안 버전·"이렇게 그렸습니다" 같은 설명은 붙이지 않는다. 받는 쪽은 마크업을
그대로 잘라 쓴다.

---

## 1. 작업 절차 — 먼저 글자로 그리고, 그 다음 rect로 옮긴다

**바로 `<rect>`부터 쓰지 마라.** 좌표를 머릿속으로 쌓아 올리면 어긋난 걸 알아챌
방법이 없다. 글자로 먼저 그리면 세어서 확인할 수 있다.

### 1단계 — 24×24 ASCII 격자를 그린다

**정확히 24줄, 각 줄 정확히 24글자.** 문자 하나가 색 하나다. 문자는 5개까지:

| 문자 | 뜻 |
|---|---|
| `.` | 기본색 (요청받은 그 색) |
| `i` | 밝은 면 |
| `o` | 어두운 면 |
| `O` | 가장 어두운 면 |
| `x` | 강조색 (필요할 때만) |

### 2단계 — 격자를 세어서 점검한다

글자니까 실제로 셀 수 있다. **여기서 다 고치고 넘어간다.**

- 줄이 24개인가? 각 줄이 24글자인가?
- `.`이 **346개 이상**인가? (576칸의 60%. 기본색이 지배해야 한다)
- 가장 얇은 형태가 **가로·세로 모두 2칸 이상**인가? 1칸짜리 선이나 점은
  0.75배 축소에서 사라진다.
- 서로 다른 두 형태 사이의 간격도 2칸 이상인가? 1칸 틈은 축소되면 메워진다.
  **비스듬히 다가서는 경우를 빠뜨리기 쉽다.** 확인법: 한 형태의 칸 하나를 골라
  **그 칸을 한가운데 둔 5×5 정사각형**(상하좌우로 2칸씩)을 그려 보고, 그 안에
  다른 형태의 칸이 하나라도 있으면 간격이 부족한 것이다. 형태의 모든 칸에 대해
  본다. 8방향만 훑으면 가로 2칸·세로 1칸처럼 비스듬한 접근을 놓친다.
- 격자를 그냥 읽었을 때 그게 그 물질로 보이는가?
- 쓴 문자가 5종 이하인가?

**틀렸으면 격자를 고친다.** rect로 옮긴 뒤에 고치려 하지 마라.

### 3단계 — 격자를 rect로 옮긴다

1. **타일 전체를 기본색으로 까는 rect를 맨 앞에 하나 놓는다:**
   `<rect x="0" y="0" width="24" height="24" fill="#기본색"/>`
   이 한 줄이 빈 칸을 원천적으로 없앤다. 나머지는 전부 이 위에 덧칠하는 것이지,
   조각을 이어 붙이는 게 아니다.
2. **`.`이 아닌 칸만** 옮긴다. `.`은 1번이 이미 칠했으므로 건드리지 않는다.
3. **같은 색 가로 런 하나 = rect 하나.** `y`행의 `x`부터 연속으로 같은 문자가
   `w`칸이면 `<rect x="x" y="y" width="w" height="1" fill="#색"/>`.
4. `x`·`width`·색이 같은 런이 세로로 이어지면 **`height`를 늘려 하나로 합친다.**
   덩어리진 형태는 이렇게 하면 rect가 몇 개 안 나온다.

**배경 rect 말고는 rect끼리 겹치지 않는다.** 격자에서 옮기면 자동으로 지켜진다 —
칸 하나에 색이 하나뿐이므로. 겹쳐 그려도 화면에는 제대로 나오지만, 그러면 면적을
더해서 확인할 수 없게 된다(가려진 부분까지 세어진다). **네가 결과를 볼 수 없으니
셀 수 있는 상태를 유지하는 쪽이 중요하다.**

## 2. 하드 규격

| 항목 | 값 |
|---|---|
| 루트 | `<svg>` 하나. XML 선언(`<?xml …?>`)·DOCTYPE **없이** |
| `viewBox` | `0 0 24 24` — **정사각 고정** |
| 요소 | **`<svg>`와 `<rect>` 둘뿐** |
| 좌표·크기 | `x` `y` `width` `height` 모두 **0 이상 정수**, `width`/`height`는 1 이상 |
| 범위 | `x + width ≤ 24`, `y + height ≤ 24` |
| 속성 표기 | 값은 **큰따옴표**로 감싼다 (`x="0"`). 홑따옴표 금지 |
| rect 표기 | `<rect …/>` 로 **자기닫는다.** `<rect …></rect>` 금지 |
| rect 속성 | `x` `y` `width` `height` `fill` **다섯 개뿐, 각각 정확히 한 번씩.** 다른 속성도, 같은 속성을 두 번 쓰는 것도 금지 |
| 색 | `fill="#rrggbb"` — 6자리 **소문자** 16진수. 이름 색·`rgb()`·3자리·8자리 금지 |
| 첫 rect | **타일 전체를 덮는다**: `<rect x="0" y="0" width="24" height="24" fill="#기본색"/>` |
| 겹침 | 첫 rect 위를 덧칠하는 것 외에 **rect끼리 겹치지 않는다** — 겹치면 면적을 더해서 기본색 60%를 확인할 수 없게 된다 |
| 개수 | rect **100개 이하** |
| 색 수 | **5개 이하** |
| 파일명 | 물질 영문명 kebab-case + `.svg` (예: `dry-ice.svg`) |

`<svg>` 태그의 `width` / `height` / `xmlns` / `shape-rendering`은 **무엇이든
상관없다.** 받는 쪽은 `<rect>` 목록만 읽고 래퍼를 다시 씌운다.

## 3. 절대 쓰지 않는 것

**이 문서에서 가장 자주 깨지는 부분이다.** "SVG 아이콘"이라는 말을 들으면 반사적으로
`<path>`·`<circle>`·그라디언트를 쓰게 되는데, 여기서는 전부 실패다. 요소는
`<svg>`와 `<rect>` **둘뿐이고**, 예외가 없다.

**요소** — `<path>` · `<circle>` · `<ellipse>` · `<polygon>` · `<polyline>` ·
`<line>` · `<g>` · `<defs>` · `<style>` · `<filter>` · `<mask>` · `<clipPath>` ·
`<use>` · `<image>` · `<text>` · `<title>` · `<linearGradient>` · `<radialGradient>`
· 주석(`<!-- -->`)

**속성** — `id` · `class` · `style` · `transform` · `rx` · `ry` · `opacity` ·
`fill-opacity` · `stroke` 계열 · `fill="none"` · `url(#…)` · CSS 변수 ·
외부 파일/폰트/URL 참조

### 왜 취향이 아니라 기술적 제약인가

이 SVG는 파일로 로드되지 않는다. **마크업이 HTML 문서에 그대로 인라인 삽입되고,
같은 마크업이 한 화면에 여러 벌 동시에 존재할 수 있다.**

- `id`와 `url(#…)`는 자기 복제본과 이름이 충돌한다. 그라디언트·마스크·필터가
  전부 이 방식이라 통째로 못 쓴다.
- 인라인 SVG 안의 `<style>` 규칙은 그 SVG가 아니라 **문서 전체에 적용된다.**
- 반투명·미채색 fill은 뒤 배경을 비치게 하는데, 그 배경색은 선택 여부에 따라
  바뀐다 — 클릭할 때마다 아이콘 색이 변하게 된다.
- 받는 쪽 파서는 `<rect>`의 다섯 속성만 읽는다. 나머지는 소리 없이 버려진다.

**그라디언트가 필요하면** 같은 색 계열 rect를 3~5장 겹쳐 계단으로 만든다.
**외곽선이 필요하면** `stroke` 대신 어두운 rect를 2칸 두께로 두른다.

## 4. 그리기 규격

### 크기

- **최소 특징 두께 2칸.** 1칸 선·점은 축소에서 사라진다. 외곽선도 2칸.
- **형태 요소는 3~4개까지.** 18px에 그 이상 안 들어간다.
- 대각선은 **2칸씩 계단**으로 내린다(가로 2칸 × 세로 1칸 단위). 1칸 계단은 끊긴다.

### 색

- **기본색이 면적의 60% 이상.** 사용자는 이미 그 색으로 물질을 외우고 있다.
- 파생색은 기본색에서 **밝기만** 옮겨 만든다. 색상(hue)을 크게 틀지 않는다.
- 한 면에 명암 **3톤 이하**.
- **순백 `#ffffff` / 순흑 `#000000`을 넓게 쓰지 않는다.** UI가 어두워 튄다.
  밝은 끝은 `#e8e8ee`, 어두운 끝은 `#0d0d12`.

### 형태

- **광원은 왼쪽 위.** 밝은 면은 위·왼쪽, 그림자는 아래·오른쪽.
- 입체감은 그라디언트가 아니라 **띠·이음매·면 분할**로 낸다.
- **글자·숫자·기호 금지.** 18px에서 안 읽히고, 앱이 한국어/영어를 전환하므로
  번역과 충돌한다. (이 금지는 **이 문서가 관장하는 24칸 칩**에 대한 것이다. 월드 타일은
  셀 크기가 줌에 따르는 다른 표면이고, 거기에 글자가 들어간 그림이 **딱 하나** 있다 —
  TNT의 종이 띠. 그건 저장소 쪽 기록이고, 여기 발주와는 무관하다.)
- **물질 자체를 그린다. 장면을 그리지 않는다.** 불꽃·연기·폭발·반짝임·궤적은
  그리지 않는다 — 게임 안에서 그건 실제로 시뮬레이션되는 별개의 입자다.

### 대비 확인용 참조값

아이콘 뒤·주변에 실제로 오는 색이다. 이 위에서 형태가 보여야 한다.

| 위치 | 색 |
|---|---|
| 칩 배경(평소) | `#1b1b22` |
| 칩 배경(선택됨) | `#232b3a` |
| 타일 테두리 | 흰색 15% 불투명, 1px, 모서리 반경 4px |
| 게임 캔버스 바탕 | `#101016` |

## 5. 출력 전 최종 점검

마크업을 **다시 읽으면서** 확인한다. 전부 읽어서 확인 가능한 것들이다.

- [ ] 첫 줄이 `<svg …viewBox="0 0 24 24"…>`, XML 선언·DOCTYPE 없음
- [ ] `<rect`와 `<svg` 외의 `<` 가 **하나도** 없음 (주석 포함)
- [ ] 모든 rect가 `x` `y` `width` `height` `fill` 다섯 속성만, 전부 큰따옴표
- [ ] 모든 좌표·크기가 정수이고, `x + width ≤ 24` / `y + height ≤ 24`
- [ ] 모든 `fill`이 `#` + 소문자 6자리
- [ ] **맨 앞 rect가 `x="0" y="0" width="24" height="24"`**
- [ ] 서로 다른 `fill` 값이 5개 이하, rect 100개 이하
- [ ] 주석(`<!-- -->`)이 하나도 없음
- [ ] §3의 요소·속성이 하나도 등장하지 않음
- [ ] 배경 rect를 뺀 나머지가 서로 겹치지 않고, 그 **면적 합이 230칸 이하**
      (= 기본색 60% 이상. `width × height`를 전부 더해서 확인한다)
- [ ] 가장 얇은 rect의 `width`와 `height`가 둘 다 2 이상
      (2칸 계단으로 만든 대각선의 `height="1"`은 예외)
- [ ] 글자·숫자 없음, 불꽃·연기 이펙트 없음
- [ ] 파일명이 지정된 kebab-case와 정확히 일치

마지막으로 **1단계의 ASCII 격자를 다시 읽어라.** 그게 그 물질로 보이지 않으면
마크업이 아무리 규격에 맞아도 실패다.
