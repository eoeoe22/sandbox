# 스냅샷 — 저장 슬롯 · 파일 내보내기/불러오기 · 화면 맞춤

자동 저장(`particle-sandbox:world:v1`, [FEATURES.md](./FEATURES.md#진행상황-로컬스토리지-저장복원))과
별개로 운영되는 **이름 붙인 세이브 슬롯** 계통 전부를 다룬다. 구현은
`src/state/snapshots.ts`(슬롯 저장소) · `snapshotFile.ts`(파일 포맷) ·
`snapshotFit.ts`(리샘플·배치)와 UI인 `components/SaveSlots.svelte`(목록) ·
`components/SnapshotLoad.svelte`(불러오기 미리보기 모달)에 나뉘어 있다.

---

## 1. 저장 슬롯 (localStorage)

컨트롤 패널의 **저장** 버튼(재생 제어 그룹, 아이콘 `bi-collection`)이 여는 모달
하나에서 저장·불러오기·수정·삭제·내보내기·가져오기를 모두 처리한다. 만들어둔
구조물·반응 씬 등을 "이어하기"가 아니라 **독립된 세이브 슬롯**으로 보관하는 것이
목적이다.

- 저장 키는 `particle-sandbox:snapshots:v1`, 상한 **50개**(`MAX_SNAPSHOTS`).
- 월드 페이로드는 자동 저장과 **완전히 동일한** RLE+base64 봉투(`serializeWorld`)
  — 셀·온도·`aux`(16비트, `aux`/`auxHi` 두 평면)·겹침 `overlay`/`overlayAux` 및 독립 오브젝트(`obj` 배열; 고무공·드럼통·다이나마이트·연막탄·나무상자·화염병 등).
- 슬롯 메타는 `id` · `name`(≤40자) · **`desc`(≤200자)** · `createdAt` · `w`/`h` ·
  `thumb`.
- 스토리지 미지원·용량 초과는 조용히 실패한다(`null` 반환 → UI가 빨간 flash).
- 스냅샷 불러오기 시 `snapshotFit` (`resampleScene`, `placeScene`) 과정에서 독립 오브젝트의 좌표·크기·질량·관성모멘트도 격자 스케일에 맞추어 자동 리샘플링 및 크롭 배치된다.

### 설명(`desc`) 필드

이름만으로는 "이게 뭘 하는 씬인지"가 안 남는다 — 특히 파일로 남에게 넘길 때.
저장 폼의 두 번째 입력칸이 설명이고, 카드/행에도 함께 표시되며(갤러리는 2줄
클램프, 목록은 1줄 말줄임), 연필 버튼은 이름과 설명을 **함께** 고치는 폼으로
바뀐다(`updateSnapshot`). 빈 문자열로 저장하면 필드 자체가 지워진다. `desc`가
없는 구버전 슬롯은 그대로 유효하다(옵셔널 필드).

### 썸네일

저장 시점 캔버스를 함께 찍는다. 전체 캔버스가 아니라 **샌드박스 영역(device
px)만 crop**하고(`Game.ts`가 `layout.deviceRect`로 구한 rect를
`captureThumbnail`에 전달) 160px 폭 JPEG(q0.55, 장당 ~5–10KB) data URL로
저장한다. 캡처 실패·구버전 슬롯은 `bi-image` 플레이스홀더로 대체되고 저장 자체는
정상 진행된다.

### 보기 방식

세그먼티드 토글(`radiogroup`/`radio`)로 두 가지. **갤러리 뷰**(기본, `bi-grid`)는
큰 썸네일 카드를 auto-fill 그리드로 펼치고 호버/포커스 시 액션이 오버레이로
뜬다(터치 기기는 `@media (hover: none)`에서 항상 표시). **목록 뷰**(`bi-list-ul`)는
작은 썸네일(48×36)을 앞세운 행이다. 두 뷰 모두 액션은 **불러오기 · 내보내기 ·
수정 · 삭제** 4개.

## 2. 파일 내보내기 / 불러오기

로컬스토리지는 그 브라우저 안에서만 산다 — 기기를 바꾸거나 남에게 씬을 넘길
방법이 없었다. 슬롯을 파일로 쓰고 읽는 경로를 추가했다.

### 파일 포맷 — `.psbx.json`

확장자는 `psbx`(**P**article **S**and**B**o**X**) + `.json`. 앞 조각이 "우리 것"을
표시하고, 뒤 `.json`이 에디터·깃허브·OS 미리보기가 실제 내용(JSON)을 그대로
인식하게 한다. 별도 압축이나 바이너리 패킹은 하지 않는다 — 월드 봉투가 이미
RLE+base64로 줄어 있고, 헤더는 사람이 열어 읽을 수 있는 편이 낫다.

```jsonc
{
  "format": "particle-sandbox-snapshot", // 우리 파일임을 식별하는 마커
  "v": 1,                                // 컨테이너 버전 (페이로드는 자체 v를 가짐)
  "title": "용암성 / 3층",                // 파일명이 되는 제목
  "description": "우측 스위치를 켜면 시작", // 간단한 설명
  "createdAt": 1700000000000,
  "w": 640, "h": 360,
  "thumb": "data:image/jpeg;base64,...",  // 선택
  "world": { "v": 1, "cells": "...", "temp": "...", "aux": "...", ... }
}
```

**파일명 = 제목.** `fileNameFromTitle`이 제어문자와 `<>:"/\|?*`를 공백으로
바꾸고, 공백을 접고, 끝의 점/공백을 떼고, 60자로 자르고, 윈도 예약 장치명
(`CON`/`PRN`/`AUX`/`NUL`/`COM1`…)이면 `snapshot`으로 폴백한다. 한글은 그대로
둔다 — 제목의 주된 케이스이고 브라우저 다운로드가 잘 처리한다.

### 내보내기

각 슬롯 액션의 `bi-download` 버튼 → `exportSnapshot(id)`가
`{filename, text}`를 만들고 `downloadTextFile`이 Blob object URL + 합성 앵커
클릭으로 내려받는다(URL은 다음 틱에 revoke).

### 가져오기

모달 상단의 **파일 불러오기** 버튼(`bi-folder2-open`)이 숨은
`<input type="file">`을 클릭하고, **패널 어디에나 파일을 드롭**해도 같은
경로를 탄다(드래그 중에는 점선 아웃라인 표시).

> **불러온 파일은 캔버스에 즉시 반영하지 않고 목록에만 추가한다.** 가져오기가
> 작업 중인 캔버스를 날려버리면 안 되기 때문 — 새 항목이 목록에 생기고, 실제
> 적용은 사용자가 불러오기를 누를 때 일어난다.

검증은 `parseSnapshotFile`이 담당하며, 다음은 전부 **거부**한다(반쯤 들어온
씬보다 거절이 낫다):

| 케이스 | 처리 |
| --- | --- |
| JSON이 아님 / 배열 / 무관한 객체 | 거부 (`invalid`) |
| `format` 마커 불일치 | 거부 |
| 컨테이너 `v`가 현재보다 높음 | 거부 (추측하지 않음) |
| `world`가 없거나 `deserializeWorld` 실패 | 거부 |
| 32MB 초과 (`SNAPSHOT_FILE_MAX_BYTES`) | 거부 (`importTooBig`) |
| 슬롯 50개 꽉 참 | 거부 (`limit`) |
| `title`/`description` 과다 길이 | 40 / 200자로 절단 후 수용 |
| `thumb`이 인라인 이미지 data URL이 아님 | **썸네일만 버리고** 수용 |

마지막 줄이 중요하다: 파일은 **남이 쓴 것**이므로 `thumb`을 그대로 `<img src>`에
꽂으면 원격 URL 페치나 `javascript:` 스킴을 파일 작성자가 고를 수 있게 된다.
`^data:image/(jpeg|png|webp);base64,…$` 에 맞는 값만 통과시킨다.

가져온 항목은 **새 id**를 받는다 — 같은 파일을 두 번 넣으면 독립된 슬롯 두 개가
되지, 하나를 덮어쓰지 않는다. 제목·설명·썸네일·원본 생성시각은 파일에서 오고,
제목이 비어 있으면 파일명(확장자 제거)을 쓴다.

## 3. 불러오기 — 미리보기 모달 + 화면 맞춤

사용자마다 화면비도 해상도도 다르고, `해상도`(cellScale) 설정과 사이드바/하단바
레이아웃까지 그리드 크기를 움직인다. 그래서 공유받은 스냅샷이 현재 샌드박스와
같은 크기인 경우가 사실상 없다. 예전에는 `Grid.resizeFrom`의 **왼쪽 아래 기준
복사**만 있어서, 울트라와이드에서 만든 씬을 폰에서 열면 "장면의 왼쪽 아래
귀퉁이"만 보였다 — 작아진 세이브가 아니라 깨진 세이브로 읽힌다.

**어떻게 앉힐지에 정답이 없으므로 추측하지 않는다.** 불러오기를 누르면 캔버스를
건드리기 전에 `SnapshotLoad.svelte` 모달이 열려, **실제 결과 미리보기**를 보면서
직접 고르게 한다.

### 배치(placement) 모델

모드마다 다른 코드가 있는 게 아니라, 전부 **하나의 배치값**으로 환원된다:

```ts
interface SnapshotPlacement {
  cw: number; ch: number;   // 장면을 리샘플할 크기 (목적지 셀 단위)
  offX: number; offY: number; // 목적지에서의 좌상단 (음수 가능)
}
```

캔버스 밖으로 나간 부분은 잘리고, 장면이 닿지 않는 자리는 빈칸으로 남는다 —
"자르기"와 "공백으로 늘리기"에 별도 분기가 없다. 세 모드는 이 값을 만드는 방법의
차이일 뿐이다.

| 모드 | 배치 | 기본 |
| --- | --- | --- |
| `auto` — **자동 맞춤** | 종횡비 유지, 전체가 들어가도록 압축/확대 | ✅ |
| `manual` — **수동** | 사용자가 배율(연동 또는 축별)과 위치를 직접 지정 | |
| `simple` — **원본 크기** | 1:1, 넘치면 자르고 모자라면 빈칸 | |

`auto`/`simple` 모두 **가로 중앙 · 바닥 정렬**이다. 중력이 아래를 향하므로 여백은
장면 위쪽에 둬야 바닥에 쌓인 더미가 계속 바닥에 있다. 선택한 모드는
`$snapshotFit`으로 localStorage에 저장되어 다음 불러오기 때 그 탭으로 열린다
(구버전 값 `fit`/`crop`/`stretch`는 각각 `auto`/`simple`/`manual`로 마이그레이션).

### 미리보기

모달의 캔버스는 **목적지 그리드 해상도 그대로**(`width={dstW} height={dstH}`,
`image-rendering: pixelated`) 그린다. 중요한 건 이게 근사치가 아니라는 점이다 —
미리보기는 적용과 **같은 `resampleScene` 결과를 같은 `sceneClip` 사각형으로**
칠하고, 확정 시에는 그 캐시된 장면을 그대로 `placeScene`에 넘긴다. 그래서 "보이는
게 그대로 들어간다"가 말이 아니라 성질이고, 검증 하네스가 실제로 이걸 확인한다.

성능상 `resampleScene`(다수결 투표)과 `placeScene`(블릿)을 나눠 뒀다. **패닝은
리샘플 결과를 바꾸지 않으므로**, 드래그 중에는 캐시된 장면을 다시 블릿하기만
한다 — 큰 월드에서 드래그가 끊기느냐 마느냐의 차이다. 그리기는 `rAF`로 프레임당
1회로 합친다.

### 조작

- **끌기** — 미리보기를 잡아 끌면 장면이 움직인다. CSS px 이동량을
  `dstW / rect.width`로 나눠 목적지 셀 단위로 환산한다.
- **방향키** — 1칸씩, Shift와 함께면 10칸씩. 포인터 없이도 위치를 잡을 수 있게.
  드래그 표면은 `<div role="application">`이 아니라 **실제 `<button>`** 이다 —
  진짜 컨트롤이므로 포커스·키보드 도달성·접근 가능한 이름을 공짜로 얻는다.
- **배율 슬라이더** — log2 공간이라 한 눈금이 일정 *비율*이다. `SCALE_MIN`(0.125×)
  ~ `SCALE_MAX`(8×)이며, 자동 맞춤 배율이 그 아래인 경우(거대한 씬 → 작은 폰)
  하한을 그만큼 늘려 슬라이더가 항상 현재 배치를 표현할 수 있게 한다.
  **비율 고정**을 끄면 가로/세로가 따로 움직인다(옛 `stretch`가 여기 흡수됨).
- **프리셋** — 맞춤 / 원본 / 꽉 채우기 한 클릭.
- 배율이나 위치를 손대는 순간 모드는 자동으로 `manual`로 넘어간다. 안 그러면
  칩은 "자동 맞춤"이라 주장하는데 화면은 사용자가 옮겨놓은 상태가 된다.

배율 조절은 **장면 중심을 고정**한 채 확대/축소한다(원점으로 끌려가지 않게).

### 리샘플 규칙 (`snapshotFit.ts`)

- **셀 id**: 목적지 셀이 덮는 소스 사각형에서 **다수결**. 빈칸도 평범한 후보로
  센다 — 물질을 우선하면 축소된 먼지 구름이 통짜 블록이 되는데, 그건 얇은 전선
  한 줄을 잃는 것보다 나쁜 거짓말이다. 확대 시에는 사각형이 한 셀보다 좁아져
  자동으로 최근접 이웃이 된다(없던 물질이 생기지 않음).
- **나머지 평면**: 온도·`aux`·`overlay`/`overlayAux`는 **평균 내지 않고**, 이긴
  id를 가진 소스 셀 중 사각형 중심에 가장 가까운 **대표 셀 하나에서 통째로
  복사**한다. `aux`는 비트로 패킹된 상태 워드(Spark의 도체 id, Clone이 입양한
  물질)라 섞으면 전혀 다른, 의미 없는 상태가 되기 때문이다.
- **패스스루**: 요청 크기가 원본과 같으면 `resampleScene`이 소스 객체를 그대로
  돌려준다. `simple`과 "만든 기기에서 다시 여는" 흔한 경로는 비용이 0이다.

### 크기 상한과 앵커 순서

리샘플 크기에는 두 겹의 상한이 있다. **축별**로는 `SCALE_MAX`(8×)의 원본 크기 —
다만 **목적지보다 작아지지는 않는다**. 16×16 스케치를 360×203 샌드박스에 넣을 때
360×203까지 못 가면 "채우기"가 채우지 못하고 자동 맞춤도 맞추지 못하기 때문이다
(목적지는 `MAX_CELLS`로 이미 묶여 있다). **총 셀 수**로는 `MAX_SCENE_CELLS`(400만,
`MAX_SAVED_CELLS`와 동급) — 두 축이 동시에 8×면 원본 면적의 64배라, 큰 스냅샷에서
수천만 셀·수백 MB 타입드 배열이 된다. 면적 상한은 두 축을 함께 줄여 종횡비를
보존한다.

**상한은 오프셋을 계산하기 전에 건다.** 이 순서가 핵심이다 — 리샘플러가 실제로
만들지 않을 크기를 기준으로 오프셋을 뽑으면, 장면이 존재하지 않는 사각형에 앵커된
채 화면 구석에 처박힌다(실제로 "채우기"가 아무것도 채우지 못하던 버그였다).
그래서 `centered()`가 소스 크기를 인자로 받아 **먼저 클램프하고 나서** 중앙·바닥
정렬을 계산한다. `clampPlacement()`는 손으로 만든 배치를 위한 마지막 방어선이고,
상한이 걸릴 때 좌상단이 아니라 **장면 자신의 중심을 기준으로** 줄인다.
- **한계**: 많이 축소하면 셀이 합쳐지므로 **1칸짜리 전선 같은 얇은 구조는 끊길
  수 있다.** 어떤 알고리즘을 써도 마찬가지라 모달 안내문에 그대로 적어 뒀다.
  원본을 픽셀 단위로 지켜야 하면 `simple`을 쓴다.

### 모달 겹침

이 모달은 저장/불러오기 목록 모달 **위에** 뜬다. `Modal.svelte`는 열린 다이얼로그
스택(모듈 스코프)을 들고 있어 **최상단만 Escape·Tab에 반응**한다 — 없었다면
Escape 한 번에 두 창이 같이 닫혔을 것이다.

## 4. 검증

`npm run test:snapshot-file` (`test/snapshot-file.ts`, 러너
`test/run-snapshot-file.mjs`). `npm test`에도 묶여 있다. 커버 범위:

1. **파일 왕복** — 제목·설명·생성시각·크기·썸네일이 그대로 돌아오고, 페이로드가
   셀/온도/16비트 `aux`/`overlay`/`overlayAux`까지 원본과 동일하게 복원되는지.
2. **거부** — 위 표의 모든 실패 케이스가 `null`이 되는지, 비이미지 `thumb`
   3종(원격 URL·`javascript:`·`text/html` data URL)이 버려지는지, 과다 길이
   제목/설명이 잘리는지.
3. **파일명** — 한글 보존, 구분자·제어문자 치환, 끝 점 제거, 빈 제목·예약
   장치명 폴백, 60자 상한.
4. **배치** — 동일 크기 패스스루(객체 동일성까지), `simple`이 셀을 1:1로 복사하고
   넘치면 자르는지, `auto`가 비율을 지키고 여백을 위에 두며 **바닥을 바닥에**
   두는지, 확대가 없던 물질을 만들지 않는지, 축소 후에도 물질이 남는지, 배치가
   **네 방향 모두로 화면 밖에 걸쳐도** 안 터지고 줄이 감기지 않는지(완전히 밖이면
   빈 캔버스), 그리고 1×1 소스/1×1 목적지 같은 퇴화 격자.
5. **크기 상한이 앵커를 깨지 않는지** — 축별·면적 상한이 실제로 걸리는지(면적
   상한은 종횡비 보존), 작은 스냅샷이 큰 캔버스를 **정말 채우는지**, 큰 확대가
   여전히 중앙·바닥 정렬을 지키는지, 상한이 걸린 배치가 구석이 아니라 자기
   중심을 기준으로 줄어드는지.
6. **미리보기 = 결과** — `sceneClip` 사각형 안은 장면과 일치하고 바깥은 전부
   빈칸인지를 세 가지 배치로 확인한다. 모달 미리보기가 이 사각형을 그대로 칠하기
   때문에, 이 체크가 깨지면 미리보기가 거짓말을 하기 시작한다는 뜻이다.
7. **상태 정합성** — 네 가지 배치 모두에서 빈칸에 상태 워드가 남지 않고
   `overlayAux`가 `overlay` 없이 뜨지 않는지(대표 셀 복사가 깨졌는지 잡는 체크).
