# 개발 문서 (docs)

이 폴더는 프로젝트의 상세 개발·레퍼런스 문서를 **분야별**로 나눠 담는다. **작업자(에이전트·개발자) 전용**이고 유저에게 보이지 않으므로, 구현 디테일과 설계 근거를 그대로 적는다.

읽는 사람이 다른 두 곳이 따로 있다. **유저용 설명의 정본은 인게임** — `/guide` 물질 도감과 툴팁이다([CODEX.md](./CODEX.md)). **Cloudwiki** 는 가끔 쓰는 개인용 메모장이고 더 이상 갱신하지 않으므로, 무시해도 된다.

- [ARCHITECTURE.md](./ARCHITECTURE.md) — 아키텍처 & 스택: 개요·스택·디렉터리 구조·스레딩·배포/PR 프리뷰.
- [FEATURES.md](./FEATURES.md) — 기능(UI·UX·편의): 화면비·경계 모드·HUD·브러시·컨트롤 UI·저장/복원·속도·연기·중력·오버레이·검색·즐겨찾기 등. **휠클릭 스포이드**(커서 아래의 것을 팔레트 선택으로 집어 온다 — 오브젝트 > 겹침의 호스트 > 그 외, 팔레트에 없으면 조용히 실패)와 **팔레트 물질 카드**(칩에 마우스를 올리면 `/guide` 도감 카드가 그대로 뜨고, 터치에서는 **길게 눌러 오프캔버스 시트**로 — 빠른접근 스트립은 제외)도 여기.
- [SNAPSHOTS.md](./SNAPSHOTS.md) — 스냅샷 계통: 이름 붙인 세이브 슬롯(설명 필드·썸네일·갤러리/목록 뷰), `.psbx.json` 파일 내보내기/가져오기 포맷과 검증 규칙, 불러오기 미리보기 모달(자동 맞춤·수동·원본 크기)의 배치 모델과 리샘플 알고리즘.
- [PHYSICS.md](./PHYSICS.md) — 물리·엔진 시스템: 열전도(**로그 스케일 전도율 커브** — 0~1 저작값은 그대로 두고 금속:모래 속도 격차를 2.9배→8.6배로)·어는점·밀도 변위·색상 틴트·물리 엔진 고도화 1~3차·전기(스파크) 패킹과 `aux` 16비트 확장.
- [ELECTRICITY.md](./ELECTRICITY.md) — 전기 계통(장치 쪽): 전기 장치 카테고리의 공용 활성화 규약 — **전기 세기에 관계없이 연결 부위 전역 즉시 활성화**, 공용 몸체 플러드(`engine/deviceBody.ts`)와 틱당 1회 memo, 새 장치 추가 절차, 검증 하네스. **전선(`insulated` — 옆으로 안 새는 배선), 터빈의 배선 전용 출력(`PulseGate`/`Material.wiring`), 태양광 패널(`lightPulse` — 빛으로 활성화, 배터리와 같은 박자로 발전)** 절도 여기. 배선 쪽(도체·펄스 세기 패킹)은 PHYSICS.md.
- [MATERIALS.md](./MATERIALS.md) — 물질 도감: 전체 물질과 핵심 상호작용 카탈로그(카테고리별 표·상호작용 사슬).
- [CODEX.md](./CODEX.md) — 인게임 물질 도감 페이지(`/guide`): 레지스트리를 **빌드 타임에** 훑어 물질 141종 + 오브젝트 8종(현재 수는 `npm run test:codex`가 찍는다)을 검색·필터·상세로 내놓는 정적 페이지의 구조. `Material` 필드를 수치 표(`codex/stats.ts`)·특성 카드(`codex/traits.ts`)·**의도적 제외 목록**(`codex/fields.ts`)으로 가르는 선언 카탈로그와, **어느 하나에도 안 속한 필드가 있으면 이름을 대며 실패하는 커버리지 검사**(도감의 고장은 크래시가 아니라 구멍이라서). 시뮬레이션을 페이지 번들 밖에 두는 추출 경계(props 에 함수가 없어야 하는 이유), 아이콘 `<symbol>` 스프라이트(같은 그림을 문서에 한 번만), 텍스트가 아니라 키를 실어 보내 재빌드 없이 언어가 바뀌는 구조, 설명문의 한국어 우선 정책(한국어가 원본이라 폴백도 한국어), 표시 문구가 코드와 갈라서는 자리(태그 이름·설명은 `i18n/codexTerms.ts` 한 파일에 태그별로 두 언어가 나란히 — 한쪽만 적으면 검사가 아니라 컴파일이 막는다), 오브젝트가 정직하게 다른 부분(태그 레지스트리가 없어 특성 목록만 수기). **문서 페이지의 스크롤·확대**(샌드박스의 전역 `overflow: hidden` 잠금과 핀치 확대 금지를 **캔버스를 그리는 페이지만** 옵트인하게 뒤집은 `Base.astro` 의 `app` prop — 같은 상속으로 사고가 두 번 났다, 그리고 그 대가로 필요해진 `Modal.svelte` 의 문서 스크롤 잠금 — 참조 카운팅이 **닫는 순서에 의존하면 영구히 죽은 스크롤바**가 된다)와, 곁가지로 **Node 21+ 의 `navigator` 때문에 모든 페이지가 영어로 프리렌더되던 것**도 여기서 고쳤다. **필터가 세 축**이 된 라운드도 여기(§9) — 카테고리와 **동시에 따로** 걸리는 상태(`CodexEntry.phase` — 카테고리 탭 앞 넷과 키가 같은데도 따로 실어야 하는 이유는 쇳물이 「제련」이고 산이 「액체」라서다)와 태그(AND, 접히는 패널, 칩마다 남는 개수와 0이면 잠금), 그리고 **목록은 손으로 안 적고 엔트리에서 훑어내므로 아무것도 안 걸리는 필터가 존재할 수 없다**는 것. **마크다운 복사**도 여기(§10) — 카드 하나는 상세 전부, 목록은 **요약 표 + 물질별 설명문**(전상세는 아무도 안 붙여넣는다)에 「전체 중 34종」과 무슨 필터였는지를 머리에 적는다. 수치·반응의 문장화를 화면과 클립보드가 **한 구현으로 공유**하는 `codex/format.ts`와, `t()` 가 없는 키를 키 그대로 돌려준다는 사실을 역이용해 두 로케일 × 134장을 전부 찍어 보는 검사도 거기. **카드가 페이지를 나간 라운드**도 여기(§11) — 상세 모달의 본문을 `components/CodexCard.svelte` 로 들어내 **샌드박스 팔레트의 호버 카드와 한 컴포넌트**로 만들고(줄여 다시 쓴 요약이 아니라 같은 카드다), 그 카드가 필요로 하는 산문 ~68KB 는 `i18n/codexLazy.ts` 의 동적 import 로 **첫 호버 때** 받아 온다 — §1 의 배럴 핀이 못 잡는 사각(아일랜드가 `i18n/codex` 를 직접 import 하는 경로)이 정확히 이 경우라서, 여기서는 검사 대신 빌드 산출물로 확인한다. 이어서 **상세가 오프캔버스가 된 것**(§11.3)과, **여백 클릭이 카드를 닫는 대신 다른 카드를 열던 버그** — `click` 이 `pointerup` 뒤에 오는데 그 사이 오버레이가 DOM 에서 빠져 클릭이 그리드에 떨어지고 있었다 — 를 공용 `Modal` 에서 고친 것도 거기. **두 번째 탭 「게임 가이드」**도 여기(§12) — 물질 개별이
아니라 격자·상태·겹침·열전도·도구처럼 물질들이 공유하는 규칙을 다루는 정적 문서
(`GameGuideDoc.svelte`)를 물질 도감 옆에 얇은 탭 스위처(`GuidePage.svelte`, `?tab=basics`
딥링크)로 붙였다 — 새 라우트도 시작 메뉴의 새 항목도 아니다. 본문은 `i18n/guideDoc.ts`
한 파일에 두 언어가 `GuideDocText`를 나란히 `satisfies`하는 형태로 산다(codex 처럼 파일을
가르지 않은 이유는 §12.2). 헤더의 **마크다운 복사** 버튼(§12.4)은 그 값에서 그대로 문서를
조립해 화면과 클립보드가 갈라서지 않게 하며, 클립보드 쓰기 자체는 도감의 복사 버튼과
`src/lib/clipboard.ts`를 공유한다. 검증은 `npm run test:codex`. **그 탭의 설명 옆에서
도는 데모 여섯**도 여기(§13) — 스크린샷 자리에 GIF 가 아니라 **진짜 엔진**을 끼워 넣어
(`game/guideDemo.ts` + `GuideDemo.svelte`) 돌로 선을 긋는 브러시·쌓이는 모래·넘치는 그릇·오르는
연기·체를 통과해 모래에 스미는 물(그리고 체를 못 넘고 그 위에 쌓이는 모래)·아래의 불에서부터
달아오르는 히트파이프 띠를 각자의 설명 옆에서 돌린다. 본
게임과 **반대로 칸 수를 고정하고 칸 크기를 화면에 맞추는** 이유(대본이 격자 크기의 비율로
짜여 있어서), 파이프 길이를 90칸에서 56칸으로 줄인 실측 근거(5초 뒤 반대쪽 끝 24℃ → 142℃),
화면 밖에서 멈추는 규칙과 움직임 최소화의 정지 화면, **컴포넌트를 동적 import 로
받는 이유**(정적으로 매달면 물질 도감만 보고 나가는 사람도 시뮬레이션을 내려받는다), 그리고
**「고체」 카드가 벽이 아니라 돌을 긋는 이유**(벽은 파괴도 반응도 상변화도 없는 예외라 상태의
대표로는 오해를 부른다 — 벽은 그릇과 테두리로만 남는다). **브러시 속도가 선의 굵기를 정하는
것**(원판의 가장자리 줄이 한 칸이라 걸음이 1칸을 넘으면 선 위아래가 패이고, 가운데만 보는
검사로는 안 잡힌다)과 **액체가 넘친 뒤 4초를 더 보여 주는 것**(결론은 넘치는 사건이 아니라
가득 찬 그릇이다), **겹침 장면에 체가 한 줄 걸리는 이유**(체는 가루를 막고 액체만 겹침 슬롯으로
통과시키는 고체라, 물이 지나는 동안 화면에 「고체 안에 든 액체」가 그대로 보이고, 끝에 부은 모래는
그 위에 쌓여 대조군이 된다)도 같은 절에 있다. 검증은 `npm run test:guidedemo`. **카드가 자기 물질로 도는 데모**도 여기(§14) —
도감 상세 모달의 설명과 수치 사이에 같은 엔진을 끼워 넣되, 상태별 대표 물질(돌·모래·
물·연기)이 아니라 **카드의 실제 물질**로 돌게 했다(철 카드는 철이). `GuideDemoWorld` 가
`subjectId` 를 주입받아 상태 4종 tick 이 `this.subjectId` 를 쓰도록 일반화됐고, basics
탭은 아무것도 넘기지 않아 `defaultSubject(kind)` 로 기존 여섯 장면이 한 줄도 안 바뀐다
(검사도 그대로 통과). 카드는 `demo` 스니펫 자리만 비우고 엔진을 모르며, 끼워 넣는 것은
가이드 모달(`Codex.svelte`)뿐 — 팔레트 호버 카드는 변경 없다. 카드의 실제 물질을
그리려면 **전체 물질 배럴**(약 150종)이 필요하므로(경량 데모 배럴 9종으로는 검은 칸이
된다) 가이드 모달이 마운트 뒤 동적 import 로 배럴과 엔진 청크를 끌어온다(§13.6 의 같은
패턴). **물질별 맞춤 데모**도 여기(§15) — 상태별 단일 동작이 아니라 그 물질이 왜
흥미로운지를 보여주는 복합 타임라인 다섯 종(벽은 TNT·산·녹은 U235 임계폭주에 견디고,
흑요석은 용암 급냉 생성과 폭발 내성의 두 액트, 소금물·설탕물은 용해, 베이킹소다는 산
중화와 반죽 반응). phase 기반이 아니라 **물질 id → 맞춤 kind** 오버라이드 맵(id 리터럴로,
정적 배럴 의존성이 첫 청크에 들어가지 않게)으로 가고, 흑요석·소다의 두 액트는 대본
틱 안에서 `grid.clear()` 후 두 번째 액트 배치를 직접 놓는 장면 전환으로 이어진다.
특히 벽 데모의 **녹은 U235 를 WALL 울타리 안에 가두는 설계** — 액체가 흘러 흩어지면
이웃이 줄어 임계에 못 다다르므로 울타리가 가둬야 한다 — 가 이 절의 핵심이다.
- [PETROCHEMISTRY.md](./PETROCHEMISTRY.md) — 석유화학 라인: 원유 분별증류(boil-in-place·reflux·유분별 수율)와 그 후속 도전과제인 **열분해 → 중합**(에틸렌·촉매·폴리에틸렌) — 크래킹 온도 게이트와 화력 위계, 중합 발열에 의한 자기 정지와 냉각, 사슬 세대 제한, 산물의 **내산성**(산 위에 뜨는 유일한 내산 재료).
- [MATERIAL-SYSTEMS.md](./MATERIAL-SYSTEMS.md) — 물질군·시스템 노트: 물질군 도입 라운드의 엔진/인프라 설계 노트(공용 헬퍼·데이터 태그·크로스-물질 메커니즘)와 플레이 가이드 링크. **부식 패스 공용화**(`materials/corrosion.ts` — Acid·Acid Vapor·Acid Slime이 한 구현을 공유하고 세기·수소 갈림만 `CorrosionSpec` 데이터로 둔다)도 여기. **반물질 전면 소멸**(Wall·Void만 남기고 방폭·무적·기체 예외를 모두 없앤 라운드 — 부산물인 섬광에 `aux` 표식을 찍어 자기잠식을 막는다, 검증 `npm run test:antimatter`)도 여기. **소화 계통 전면 개편**(물을 부어도 증발만 빠르고 안 꺼지던 문제 → 공용 소화 패스 `materials/suppress.ts`와 **화재 등급** `Material.fireClass`: 불꽃 소화 1:1화, 연료 덩어리 심부까지 냉각하는 플러드, 소화 중인 물의 비등 차폐, Snow/Ice 소화 능력 부여, 검증 `npm run test:extinguish`)도 여기. **Metal Powder → Iron Powder 개명**(id 105 불변 — 한국어명이 원래부터 `철가루`였고 영어 쪽을 거기 맞췄다. 세이브 호환과, 표시명을 문자열로 잡던 검사 두 곳의 파급)도 여기. **겹침(overlap) 개선 라운드**(스며든 액체가 충격파에 지워지던 문제 → 파편이 겹침을 나르는 `Material.overlapCarrier`와 크레이터의 `resolveSoaked`, 스며든 액체의 상호작용이 꺼져 있던 문제 → 겹침 너머 반응 테이블 `tryReactSoaked`와 유체 훅 `Material.overlapUpdate`/스며든 산의 부식, 검증 `npm run test:overlap`)도 여기 — 그
후속 라운드에서 **뜬 가루 컬럼의 겹침은 알갱이가 아니라 흘수선을 따라간다**는 것(그래서
`shiftPowderColumnUp/Down`은 겹침을 일부러 안 옮긴다)과 **다이너마이트 도화선이 날아가는
파편의 비행 상태를 열로 읽어 재점화되던 버그**(`packedTemp`)까지 같이 정리했다.
  **부패·보존**(신규 3종 — 곰팡이·부패물·퇴비 + 공용 `Material.spoil`)도 여기 — 무엇이 썩는지를 성질에서 유도하지 않고 **선언**으로 둔 이유(나무가 자동으로 걸리면 지어 둔 건축물이 조용히 무너진다), 보존이 **되돌림이 아니라 멈춤**이라 확률 굴림이 아니라 카운터여야 했던 것과 그 카운터를 넣을 **안전한 aux 기본값이 없다**는 것(반죽의 필드별 aux 재조립이 새 필드를 조용히 지우던 자리 포함), 곰팡이가 아무것도 파괴하지 않는 것이 예외 목록이 아니라 **「빈칸에만, 붙을 표면이 있을 때만」 한 규칙의 따름정리**라는 것, 온도 반응을 단조에서 **35° 정점 후 감쇠**로 바꾼 이유(미지근한 곳이 최악의 보관법이 되고 살균 문턱이 절벽이 된다), 그리고 정본 `category` 가 탭이 아니라 **판정이 읽는 값**이라 퇴비가 `life` 에서 `powder` 로 내려간 것. 검증 `npm run test:spoil`. **후속 라운드(곰팡이가 먹는다)** — 침식 + 포자 가루로 바뀌면서 곰팡이가 사슬의 한 단계가 됐고(식품 → 곰팡이 → 부패물 → 퇴비), 「가루가 되면 벽을 못 덮는다」를 **붙은 것은 안 움직이고 붙을 데 없는 것만 흩날린다**로 가른 것, 부패물도 `spoil` 을 선언해 생긴 **livelock**(곰팡이 ↔ 부패물이 서로를 먹어 900초에 퇴비 0칸), 먹은 곰팡이와 그냥 자란 껍질을 `aux` 한 비트로 가르지 않으면 **돌벽이 퇴비 생성기**가 되는 것까지.

- [MATERIAL-ICONS.md](./MATERIAL-ICONS.md) — 물질 아이콘·패턴: 단색 스와치를 캔버스의 실제 질감으로 바꾸는 생성기(`render/materialSvg.ts`) — 렌더러 분기 사슬을 9×9 패치(평면 기체만 18×18 구름 실루엣)에 그대로 재생하고, 셰이딩은 `render/color.ts`로 끌어올려 렌더러와 **한 구현을 공유**한다. 그 위에 덮어쓰기 계층이 **둘** 있다. **손그림 25종**(§4.1)은 이유가 서로 반대인 두 갈래다: **개념이 정체성이라 유도할 패턴이 아예 없는 것 13종**(Void의 "삭제"는 색도 질감도 아니다)과, **인월드에서 정직하게 한 색이라 되비출 패턴이 없는 것 12종**(철판은 실제로 한 톤이라, 손그림이 그 표면에 결·면·광택을 처음으로 넣는 유일한 자리다 — 2순위 배치). **방사성 5종**(§4.2)은 그림이 아니라 **표**다 — 다섯이 서로 안 닮았고 정작 중요한 성질(벽 너머까지 방사)은 눈에 안 보이므로, 유도 타일을 18칸으로 리샘플하고 그 위에 방사능 삼엽을 굽는다. 인월드는 그대로다. `.svg`는 런타임에 로드되지 않고 모듈로 구워진다. 2순위 병렬 발주에서 **15장 전부가 규격 검수를 통과했는데 9장이 물질로 읽히지 않았다**는 기록도 §4.1에 있다 — 규격과 가독성은 다른 축이고, 깨진 방식은 거의 하나였다(타일을 무늬로 덮어 벽지가 되는 것). **계층에서 나가는 방향도 기록해 뒀다**: Wood·Mercury·Liquid Gallium은 손그림을 **철회**했다 — Wood는 `colorVary: 16`으로 유도 타일이 정직해졌고(캔버스의 나무 벽도 같이 고쳐졌다), 액체 금속 둘은 `colorVary: 0`이 의도라서 반사선 자체가 없는 질감을 주장하는 것이었다. 반대 방향은 셋이다: **Wall은 줄쌓기 벽돌을 `brickPattern`으로, Woofer는 스피커 드라이버를 `wooferPattern`으로, TNT는 폭약 무늬를 `tntPattern`으로** 칩에서 캔버스로 되돌렸다. TNT는 그 뒤 **캔버스가 칩을 앞질러 갔다** — 16×16 타일에 글자 붙은 종이 띠를 두른 다이너마이트 다발이고, **엔진에서 유일하게 수식이 아니라 비트맵인 패턴**이며 **프로젝트에서 유일하게 글자가 들어간 그림**이다(브리프의 글자 금지는 18 px 칩에 대한 것이고 월드 타일에는 닿지 않는다 — 그래서 칩에는 여전히 글자가 없다). Obsidian은 무늬 대신 **틴트 진폭을 좁히고**(14 → 6) 그 표본을 **2×2로 묶어**(`tintBlock`) 파단면이 먼지가 아니라 면으로 읽히게 했다 — 진폭과 블록 하나가 캔버스와 아이콘을 같이 바꾼다. 팔레트 126종 전수 분류, 합성 틴트가 액체의 OU 정상상태 분포를 따라가는 이유, `N = 9`·색상별 `<path>`·**세로 런 병합**(리샘플 타일을 4 KB 예산 안에 넣은 조건) 같은 크기·픽셀 정렬 결정, 남은 손그림 5종의 발주 목록(§7 — 규격 자체는 저장소 없이 넘길 수 있는 `create-svg-assets/MATERIAL-ICON-BRIEF.md`). 검증은 `npm run test:materialicons` + `npm run check:hand-icons`.
