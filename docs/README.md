# 개발 문서 (docs)

이 폴더는 프로젝트의 상세 개발·레퍼런스 문서를 **분야별**로 나눠 담는다. Cloudwiki의 "Web sandbox 프로젝트" 페이지는 이제 가벼운 소개 문서로 두고, 세부 기록은 여기에 둔다.

- [ARCHITECTURE.md](./ARCHITECTURE.md) — 아키텍처 & 스택: 개요·스택·디렉터리 구조·스레딩·배포/PR 프리뷰.
- [FEATURES.md](./FEATURES.md) — 기능(UI·UX·편의): 화면비·경계 모드·HUD·브러시·컨트롤 UI·저장/복원·속도·연기·중력·오버레이·검색·즐겨찾기 등.
- [SNAPSHOTS.md](./SNAPSHOTS.md) — 스냅샷 계통: 이름 붙인 세이브 슬롯(설명 필드·썸네일·갤러리/목록 뷰), `.psbx.json` 파일 내보내기/가져오기 포맷과 검증 규칙, 불러오기 미리보기 모달(자동 맞춤·수동·원본 크기)의 배치 모델과 리샘플 알고리즘.
- [PHYSICS.md](./PHYSICS.md) — 물리·엔진 시스템: 열전도·어는점·밀도 변위·색상 틴트·물리 엔진 고도화 1~3차·전기(스파크) 패킹과 `aux` 16비트 확장.
- [ELECTRICITY.md](./ELECTRICITY.md) — 전기 계통(장치 쪽): 전기 장치 카테고리의 공용 활성화 규약 — **전기 세기에 관계없이 연결 부위 전역 즉시 활성화**, 공용 몸체 플러드(`engine/deviceBody.ts`)와 틱당 1회 memo, 새 장치 추가 절차, 검증 하네스. **전선(`insulated` — 옆으로 안 새는 배선), 터빈의 배선 전용 출력(`PulseGate`/`Material.wiring`), 태양광 패널(`lightPulse` — 빛으로 활성화, 배터리와 같은 박자로 발전)** 절도 여기. 배선 쪽(도체·펄스 세기 패킹)은 PHYSICS.md.
- [MATERIALS.md](./MATERIALS.md) — 물질 도감: 전체 물질과 핵심 상호작용 카탈로그(카테고리별 표·상호작용 사슬).
- [PETROCHEMISTRY.md](./PETROCHEMISTRY.md) — 석유화학 라인: 원유 분별증류(boil-in-place·reflux·유분별 수율)와 그 후속 도전과제인 **열분해 → 중합**(에틸렌·촉매·폴리에틸렌) — 크래킹 온도 게이트와 화력 위계, 중합 발열에 의한 자기 정지와 냉각, 사슬 세대 제한, 산물의 **내산성**(산 위에 뜨는 유일한 내산 재료).
- [MATERIAL-SYSTEMS.md](./MATERIAL-SYSTEMS.md) — 물질군·시스템 노트: 물질군 도입 라운드의 엔진/인프라 설계 노트(공용 헬퍼·데이터 태그·크로스-물질 메커니즘)와 플레이 가이드 링크. **부식 패스 공용화**(`materials/corrosion.ts` — Acid·Acid Vapor·Acid Slime이 한 구현을 공유하고 세기·수소 갈림만 `CorrosionSpec` 데이터로 둔다)도 여기. **반물질 전면 소멸**(Wall·Void만 남기고 방폭·무적·기체 예외를 모두 없앤 라운드 — 부산물인 섬광에 `aux` 표식을 찍어 자기잠식을 막는다, 검증 `npm run test:antimatter`)도 여기. **Metal Powder → Iron Powder 개명**(id 105 불변 — 한국어명이 원래부터 `철가루`였고 영어 쪽을 거기 맞췄다. 세이브 호환과, 표시명을 문자열로 잡던 검사 두 곳의 파급)도 여기. **겹침(overlap) 개선 라운드**(스며든 액체가 충격파에 지워지던 문제 → 파편이 겹침을 나르는 `Material.overlapCarrier`와 크레이터의 `resolveSoaked`, 스며든 액체의 상호작용이 꺼져 있던 문제 → 겹침 너머 반응 테이블 `tryReactSoaked`와 유체 훅 `Material.overlapUpdate`/스며든 산의 부식, 검증 `npm run test:overlap`)도 여기 — 그
후속 라운드에서 **뜬 가루 컬럼의 겹침은 알갱이가 아니라 흘수선을 따라간다**는 것(그래서
`shiftPowderColumnUp/Down`은 겹침을 일부러 안 옮긴다)과 **다이너마이트 도화선이 날아가는
파편의 비행 상태를 열로 읽어 재점화되던 버그**(`packedTemp`)까지 같이 정리했다.
- [LIFE.md](./LIFE.md) — 생명 계통(자라는 것들): Plant의 가지치기 L-시스템 성장(끝만 자람·구간·분기·활력·혼잡 제한), 물 모델(마시기·뿌리 뻗기·위킹·감소)과 소금물 배제, 곁순 재발아·씨앗 결실, `soil.ts`의 "밭이 젖었는가" 판정(스며든 물 찾기), Seed 발아 개편(흙 종류 확대·발아 진행도 색 피드백·절대 낭비 없음), **Coral**(소금물 속 유사 프랙탈 성장)과 **백화**(고온·브라인 상실)·백화 산호 재군체화, 그리고 **방사선 피폭**(방사능 카테고리 전 물질이 주변 6칸의 생명을 죽임 — 태그 `radiation`/`radiationDeath`/`radiationHit`으로 엔진이 구동, **가루·액체는 통과하고 고체만 차폐**, 방사성 물질은 자기차폐라 더미는 표면만 방출, 사체는 각자 원래 죽던 모습대로·산호만 즉사가 아닌 백화·나노봇과 슬라임 두 종은 면역). 검증은 `npm run test:plantcoral` · `npm run test:radiation`.
- [MATERIAL-ICONS.md](./MATERIAL-ICONS.md) — 물질 아이콘·패턴: 단색 스와치를 캔버스의 실제 질감으로 바꾸는 생성기(`render/materialSvg.ts`) — 렌더러 분기 사슬을 9×9 패치(평면 기체만 18×18 구름 실루엣)에 그대로 재생하고, 셰이딩은 `render/color.ts`로 끌어올려 렌더러와 **한 구현을 공유**한다. 그 위에 덮어쓰기 계층이 **둘** 있다. **손그림 25종**(§4.1)은 이유가 서로 반대인 두 갈래다: **개념이 정체성이라 유도할 패턴이 아예 없는 것 13종**(Void의 "삭제"는 색도 질감도 아니다)과, **인월드에서 정직하게 한 색이라 되비출 패턴이 없는 것 12종**(철판은 실제로 한 톤이라, 손그림이 그 표면에 결·면·광택을 처음으로 넣는 유일한 자리다 — 2순위 배치). **방사성 5종**(§4.2)은 그림이 아니라 **표**다 — 다섯이 서로 안 닮았고 정작 중요한 성질(벽 너머까지 방사)은 눈에 안 보이므로, 유도 타일을 18칸으로 리샘플하고 그 위에 방사능 삼엽을 굽는다. 인월드는 그대로다. `.svg`는 런타임에 로드되지 않고 모듈로 구워진다. 2순위 병렬 발주에서 **15장 전부가 규격 검수를 통과했는데 9장이 물질로 읽히지 않았다**는 기록도 §4.1에 있다 — 규격과 가독성은 다른 축이고, 깨진 방식은 거의 하나였다(타일을 무늬로 덮어 벽지가 되는 것). **계층에서 나가는 방향도 기록해 뒀다**: Wood·Mercury·Liquid Gallium은 손그림을 **철회**했다 — Wood는 `colorVary: 16`으로 유도 타일이 정직해졌고(캔버스의 나무 벽도 같이 고쳐졌다), 액체 금속 둘은 `colorVary: 0`이 의도라서 반사선 자체가 없는 질감을 주장하는 것이었다. 반대 방향은 셋이다: **Wall은 줄쌓기 벽돌을 `brickPattern`으로, Woofer는 스피커 드라이버를 `wooferPattern`으로, TNT는 폭약 무늬를 `tntPattern`으로** 칩에서 캔버스로 되돌렸다. TNT는 그 뒤 **캔버스가 칩을 앞질러 갔다** — 16×16 타일에 글자 붙은 종이 띠를 두른 다이너마이트 다발이고, **엔진에서 유일하게 수식이 아니라 비트맵인 패턴**이며 **프로젝트에서 유일하게 글자가 들어간 그림**이다(브리프의 글자 금지는 18 px 칩에 대한 것이고 월드 타일에는 닿지 않는다 — 그래서 칩에는 여전히 글자가 없다). Obsidian은 무늬 대신 **틴트 진폭을 좁히고**(14 → 6) 그 표본을 **2×2로 묶어**(`tintBlock`) 파단면이 먼지가 아니라 면으로 읽히게 했다 — 진폭과 블록 하나가 캔버스와 아이콘을 같이 바꾼다. 팔레트 126종 전수 분류, 합성 틴트가 액체의 OU 정상상태 분포를 따라가는 이유, `N = 9`·색상별 `<path>`·**세로 런 병합**(리샘플 타일을 4 KB 예산 안에 넣은 조건) 같은 크기·픽셀 정렬 결정, 남은 손그림 5종의 발주 목록(§7 — 규격 자체는 저장소 없이 넘길 수 있는 `create-svg-assets/MATERIAL-ICON-BRIEF.md`). 검증은 `npm run test:materialicons` + `npm run check:hand-icons`.
- [MATERIAL-IDEAS.md](./MATERIAL-IDEAS.md) — 물질 구상·미채택 제안: 조사·설계는 끝났지만 아직 구현하지 않은 물질/상호작용 후보(우선순위·재사용할 기존 인프라·비용과 리스크). 구현되면 이 문서에서 빼고 도감/시스템 노트로 옮긴다.
- [OBJECTS.md](./OBJECTS.md) — 독립 오브젝트 시스템: 고무공·드럼통·다이너마이트·연막탄·나무 상자(가연성·**산에 닿으면 용해**·파괴 시 조각 3개 → 톱밥)·**화염병**(불붙은 채로 스폰, 느린 충돌에도 깨지고 불붙은 알콜을 쏟음, 15초 뒤 빈 유리병), 오브젝트 물리/상호작용/브러시 연동, **전자석 인력**(강철 바디만 끌려와 매달림)과 **연막탄의 수중 연기**(액체를 밀어 올려 자리를 만듦). **평면(둥근 사각형) 충돌 형상**(드럼통 뚜껑·상자 각 면이 평면이라 서로 쌓임)과 **오브젝트끼리 충돌 파괴**. 검증은 `npm run test:woodbox` · `test:molotov` · `test:magnetobjects` · `test:smokebomb` · `test:stacking`.
- [I18N.md](./I18N.md) — 다국어(i18n): 한국어/영어 전환, 번역 테이블 구조, 카테고리 키 규칙, 새 문자열·물질·객체 번역 추가 방법.
- [WASM-ENGINE-PORTING.md](./WASM-ENGINE-PORTING.md) — 성능·이식 계획 + 착수 기록: WASM/멀티스레드 핵심 엔진 포팅 로드맵(측정→오프메인스레드→수치 커널 WASM→조건부 CA 스캔). **Phase 2 첫 커널(열확산 `diffuseHeat`)이 Rust/WASM으로 착수 완료**(§9) — 비트 동일 골든 테스트 + JS 폴백. 물질 89개는 워커 안 JS로 유지(포팅 부채 0)라는 결론은 그대로. 커널 빌드/구조는 [`wasm/README.md`](../wasm/README.md).
- [PWA.md](./PWA.md) — PWA·오프라인 지원: 매니페스트/아이콘/서비스 워커 구성과

- [PERFORMANCE.md](./PERFORMANCE.md) — 성능 계측: Phase 0 측정 하네스(인앱 패스별 프로파일러 `?perf`, 고정 벤치 장면 `?bench=`, 열 커널 JS-vs-WASM 마이크로벤치)와 **실측 결과**. 결론: 점유 장면에서 **CA 물질 스캔이 틱의 80%+** 로 지배적. **§4 활성-타일 CA 스캔**으로 그 스캔의 빈 영역을 스킵 — 비트 동일(전면 스캔과 매 틱 동일, 결정론 검증)·전형적 장면 ~1.8×·빈 장면 ~30×·밀집 중립.
